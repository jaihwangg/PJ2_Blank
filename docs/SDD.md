# SDD — Arduino 조이스틱 기반 UE 상자 이동

- 작성일: 2026-11-05
- 버전: 0.1 / 구현 전 설계 초안
- 요구사항: [PRD.md](PRD.md)
- 대상: `C:\Work\Unreal5.8\PJ2_Blank`
- 상태: 제안 설계. 소스·에셋·펌웨어는 아직 수정하지 않았다.

## 1. 설계 방향과 대안

기존 Windows 시리얼 컴포넌트를 재사용하고, 통신·조이스틱 해석·상자 이동을 분리한다. 추가 플러그인 없이 제한된 Tick 폴링으로 시작하는 것이 이번 범위의 권장안이다. 아래 선택은 사용자 승인 완료를 뜻하지 않는다.

| 방식 | 이점 | 비용·판단 |
|---|---|---|
| 기존 컴포넌트 + 제한된 Tick 수신 | 기존 코드 활용, 게임 스레드에서 이벤트 처리, 단순한 수명주기 | Tick 작업량 관리 필요. 현재 권장안 |
| 전용 수신 스레드 | 높은 데이터량에서 게임 스레드 작업 감소 | 동기화·취소·종료 처리 증가. 측정 결과 필요할 때 도입 |
| 외부 시리얼 플러그인 | 연결 기능 재사용 가능 | UE 버전 호환과 의존성 검토 필요. 현재 범위에서는 도입하지 않음 |

## 2. 구성과 데이터 흐름

```text
조이스틱 VRx/VRy
    → Uno A0/A1 → USB 시리얼
    → UArduinoSerialComponent (바이트 수신·줄 조립)
    → UArduinoJoystickComponent (파싱·보정·입력 만료)
    → BP_JoystickBox (월드 X/Y 이동)
```

시리얼 컴포넌트는 조이스틱 데이터 의미를 알지 않는다. 조이스틱 컴포넌트는 액터 위치를 변경하지 않는다. 상자 Blueprint는 COM 바이트나 메시지 형식을 해석하지 않는다.

아래 경로는 대상 UE 프로젝트 기준이며, 신규 이름은 제안이다. 기존 에셋 내부 확인 후 중복 역할을 만들지 않도록 조정한다.

| `Source/PJ2_Blank/ArduinoJoystickComponent.h/.cpp` | 신규. 메시지 검증, 축 보정, 입력 상태·만료 |

## 4. 하드웨어와 펌웨어

전원을 분리한 상태에서 다음처럼 배선한다.

| 조이스틱 핀 | Uno 핀 |
|---|---|
| GND | GND |
| +5V | 5V |
| VRx | A0 |
| VRy | A1 |
| SW | 미연결 |

펌웨어는 `Serial.begin(115200)`을 사용한다. `millis()` 경과 시간으로 20ms마다 두 채널을 읽고 메시지 하나를 전송한다. 지연된 주기를 몰아서 재전송하지 않는다. 첫 단계는 기본 10비트 ADC 범위 0~1023을 사용한다.

PC에서 포트를 열 때 Uno가 리셋될 수 있으므로 UE는 즉시 입력을 기대하지 않고 유효 메시지를 기다린다. 별도 READY/ACK 메시지는 이번 프로토콜에 추가하지 않는다.

## 5. 통신 프로토콜

| 항목 | 규칙 |
|---|---|
| 설정 | 115200 baud, 8 data bits, no parity, 1 stop bit, 흐름 제어 없음 |
| 인코딩 | ASCII |
| 형식 | `JOY,<X>,<Y>\n` |
| 예시 | `JOY,512,508\n` — 표기한 `\n`은 실제 LF 한 바이트 |
| 축 값 | 부호 없는 10진 정수, 각각 0~1023 |
| 토큰 | 정확히 3개, 첫 토큰은 대문자 JOY |
| 줄 끝 | LF 기준, LF 직전 CR 한 개는 허용 |
| 길이 | LF 제외 최대 64바이트. CR은 길이에 포함 |

빈 줄은 무시한다. 공백, 부호, 소수, 빈 축, 추가 토큰, 숫자 뒤 문자, 범위 밖 값은 거부한다. 실패를 0으로 바꾸는 느슨한 숫자 변환을 사용하지 않는다. 유효 메시지만 현재 입력과 마지막 유효 수신 시간을 갱신한다.

## 6. 시리얼 수신 설계

### 인터페이스 초안

- 기존 `bool OpenPort()`, `void ClosePort()`를 유지한다.
- 기존 `bool SendText(const FString& Text)`는 후속 양방향 단계에서 구현·검증한다. 이번 단계의 송신 경로로 사용하지 않는다. 미정의 선언으로 인한 빌드 영향은 착수 시 확인한다.
- `OnLineReceived(const FString& Line)`: 줄 끝을 제거한 메시지 이벤트.
- `OnPortStateChanged(ESerialPortState State)`: Closed / Open / Error 이벤트.
- `LastError`: 포트 실패 사유를 진단할 수 있는 문자열.

### 읽기 처리

현재 코드는 동기 핸들과 즉시 반환 읽기용 타임아웃을 설정한다. 구현 시 해당 설정을 검증하고, `ClearCommError`로 상태와 대기 바이트를 확인한 뒤 `ReadFile`로 대기 중인 바이트만 읽는다.

- 읽기 청크 최대 256바이트, Tick당 최대 1024바이트로 제한한다.
- 실제 읽힌 바이트만 처리한다. 데이터가 없으면 즉시 반환한다.
- LF 전까지 바이트를 누적하고, 완성한 줄만 이벤트로 전달한다.
- 64바이트를 초과하면 현재 줄을 버리고 다음 LF까지 폐기한 뒤 정상 조립을 재개한다.
- 한 Tick에 여러 메시지가 오면 순서대로 처리하되, 상자 이동은 최종 입력으로 한 번만 계산한다.
- API 오류 또는 통신 오류 플래그 감지 시 버퍼를 비우고 포트를 닫아 Error 상태로 전환한다.
- 열기 실패나 부분 초기화 실패 시 생성한 핸들을 반드시 해제한다.

모든 이벤트와 이동은 게임 스레드에서 실행한다. 정상 수신량에서 프레임 지연이 관찰될 경우에만 별도 작업 스레드·큐로 변경하는 후속 설계를 진행한다.

## 7. 조이스틱 해석과 보정

### 인터페이스·설정 초안

- `FVector2D Axis`: 현재 보정된 입력, 읽기 전용 Blueprint 속성.
- `EJoystickInputState InputState`: Disconnected / WaitingForInput / Receiving / Stale.
- `OnInputStateChanged(EJoystickInputState State)` 이벤트.
- 축마다 `Min`, `Center`, `Max`, `bInvert` 설정. 기본값 0 / 512 / 1023 / false.
- `DeadZone = 0.10`, `InputTimeoutSeconds = 0.5`.
- `void HandleSerialLine(const FString& Line)`: 메시지 검증 후 입력 갱신.

각 축은 `Min < Center < Max` 조건을 만족해야 한다. 잘못된 설정은 입력을 0으로 유지하고 설정 오류를 표시한다. 시작 시 자동 중심 보정은 하지 않는다. 사용자가 스틱을 기울인 채 실행하는 경우를 피하기 위해 원시 값을 확인해 수동 설정한다.

### 정규화

원시 값 r에 대해 다음을 적용한다.

```text
r >= Center: n = (r - Center) / (Max - Center)
r <  Center: n = (r - Center) / (Center - Min)
n = clamp(n, -1, 1)
abs(n) <= d: a = 0
그 외: a = sign(n) * (abs(n) - d) / (1 - d)
반전 설정 시 a = -a
```

d는 0 이상 1 미만이어야 한다. 데드존 밖을 다시 0~1로 펼쳐 경계에서 속도가 갑자기 뛰는 것을 줄인다. 첫 단계에서는 평활화를 적용하지 않아 놓았을 때 지연 없이 정지한다.

## 8. 연결과 입력 수명주기

1. Blueprint BeginPlay에서 이벤트를 먼저 연결한 뒤 OpenPort를 호출한다.
2. 열기에 성공하면 WaitingForInput, 축은 0으로 유지한다.
3. 첫 유효 JOY 메시지가 오면 Receiving으로 전환한다.
4. 단조 증가 시간을 기준으로 유효 메시지가 0.5초 없으면 Stale로 전환하고 축을 0으로 만든다. 처음부터 메시지가 없던 경우는 WaitingForInput을 유지한다.
5. Stale 상태에서 새 유효 메시지를 받으면 Receiving으로 복귀한다.
6. 포트 닫기·오류 시 Disconnected와 축 0을 즉시 반영한다.
7. 수동 재연결 시 이전 버퍼·입력·수신 시각을 초기화한다.
8. EndPlay에서 이벤트 연결과 핸들을 정리한다. ClosePort는 반복 호출 가능해야 한다.

입력 만료는 게임 일시정지에 영향을 받지 않는 시간으로 판단한다. 게임 재개 시 이동 계산 전에 만료 여부를 평가해 오래된 입력으로 한 프레임 이동하는 것도 막는다.

## 9. 상자 Blueprint 설계

- StaticMeshComponent를 루트로 하고 기본 Cube 메쉬를 사용한다.
- Simulate Physics는 끄고, 첫 검증에서는 충돌 없는 이동으로 한정한다.
- 조이스틱 컴포넌트가 입력을 갱신한 후 상자 Tick이 실행되도록 Tick 의존성을 설정한다.
- 기본 매핑은 VRx → 월드 +X, VRy → 월드 +Y이며 실제 설치 방향에 따라 반전한다.
- `Axis` 벡터 길이가 1을 넘으면 길이 1로 제한한다. 작은 입력 크기는 유지한다.
- `Delta = FVector(Axis.X, Axis.Y, 0) * MoveSpeed * DeltaSeconds`로 이동한다.
- 기본 MoveSpeed는 300 units/s, 에디터에서 변경 가능하게 한다.
- 시작 Z를 유지하며 수신 데이터가 직접 Z 또는 속도를 지정할 수 없게 한다.
- 포트 상태, 입력 상태, 원시값·보정값을 테스트 장면에서 확인할 수 있게 한다. 에디터 화면 표시와 패키지 로그를 사용하고 별도 UI 시스템은 추가하지 않는다.

테스트는 실제 책임 코드가 사용하는 파싱·보정·시간 판정 경로를 검증한다. 하드웨어가 필요한 검증을 모의 테스트 통과로 대체하지 않는다. 문서 작성 시점에는 빌드나 장치 테스트를 실행하지 않았다.

## 11. 구현 순서와 후속 확장

1. 기존 Blueprint·빌드 환경과 실제 COM 번호를 확인한다.
2. 수신·줄 조립 및 파싱·보정의 핵심 경계 테스트를 작성하고 해당 기능을 구현한다.
3. Uno 펌웨어를 작성하고 원시 입력 전송을 확인한다.
4. 상자 Blueprint와 테스트 맵을 연결한다.
5. 만료·재시도·종료·패키지 검증을 수행한다.

상자 이동이 검증된 후 별도 요구사항으로 SW 버튼과 UE→Arduino 출력 프로토콜을 설계한다. 그 단계에서 SendText 구현, 명령 검증, 응답·재시도, 출력 장치의 통신 중단 동작을 정의한다. 이번 문서는 후속 구현을 승인하거나 완료한 것으로 간주하지 않는다.
