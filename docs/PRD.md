# PRD — Arduino 조이스틱으로 Unreal Engine 상자 이동

- 작성일: 2026-11-05
- 버전: 0.1 / 구현 전 검토 초안
- 대상 프로젝트: `C:\Work\Unreal5.8\PJ2_Blank`
- 관련 설계: [SDD.md](SDD.md)
- 현재 작업: 요구사항·설계 문서 작성. 코드, Blueprint, 펌웨어 구현은 추후 진행한다.

## 1. 목적

Arduino Uno에 연결한 아날로그 조이스틱으로 Unreal Engine 5.8 테스트 맵의 상자를 움직인다. 사용자가 조이스틱을 기울이면 해당 방향으로 이동하고, 놓으면 정지하는 기본 입력 경로를 먼저 완성한다.

장기 목표는 언리얼과 아두이노의 양방향 연동이다. 이번 단계는 아두이노에서 언리얼로 전달하는 입력과 상자 이동에 집중한다.

## 2. 확인된 사항과 가정

### 사용자 확인 사항

- UE 프로젝트 경로는 위 대상 프로젝트와 같다.
- Arduino Uno를 사용한다.
- 조이스틱에는 `GND`, `+5V`, `VRx`, `VRy`, `SW` 핀이 있다. 정확한 모델명은 모른다.
- 첫 목표는 언리얼 안의 상자를 움직이는 것이다.
- 지금은 문서를 작성하고, 구현은 나중에 시작한다.

### 프로젝트에서 확인한 사항

- `.uproject`의 `EngineAssociation`은 `5.8`이다.
- `UArduinoSerialComponent`에 Windows COM 포트 열기·설정·닫기와 EndPlay 종료 처리가 있다.
- 기본 설정은 COM3, 9600 baud이다. 실제 연결 포트는 미확정이다.
- `SendText()`는 선언되어 있으나 읽은 `.cpp`에는 구현이 없다.
- Tick의 수신 처리와 조이스틱 입력 처리는 아직 없다.
- `BP_ArduinoTest.uasset`, `L_ArduinoTest.umap`이 존재한다. 에셋 내부 구성은 확인하지 않았다.
- 프로젝트 검색에서 `.ino` 파일은 발견하지 못했다.

### 제안 기본값

아래 값은 사용자 확정 요구가 아닌 초기 설계 제안이며, 하드웨어 검증 후 조정한다.

| 항목 | 초안 |
|---|---|
| 실행 환경 | Windows, UE 5.8, USB 시리얼 |
| 통신 | 115200 baud, 8N1 |
| 입력 전송 | 20ms 간격, 약 50Hz |
| 입력 | 조이스틱 두 축, 버튼 제외 |
| 이동 | 월드 X/Y 평면, Z 고정, 물리 시뮬레이션 비활성 |
| 기본 속도 | 300 Unreal units/s |
| 데드존 | 정규화한 각 축의 중심 ±0.10 |
| 입력 만료 | 마지막 유효 메시지로부터 0.5초 |
| 재연결 | 수동 재시도, 자동 재연결은 후속 범위 |

## 3. 사용 흐름

1. 전원이 분리된 상태에서 배선하고 USB로 Uno를 PC에 연결한다.
2. 펌웨어를 업로드하고 Arduino IDE의 시리얼 모니터를 닫는다.
3. 테스트 액터의 COM 포트와 보정값을 설정한다.
4. 테스트 맵에서 PIE를 시작한다.
5. 조이스틱으로 상자를 이동시키고, 연결 상태와 입력값을 확인한다.
6. PIE를 종료하면 포트가 해제된다.

## 4. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-01 | 기존 시리얼 컴포넌트를 활용해 설정된 포트를 열고 닫는다. 포트와 속도는 편집 가능해야 한다. |
| FR-02 | Uno는 A0/A1의 X/Y 입력을 주기적으로 전송한다. |
| FR-03 | UE는 분할 수신과 여러 메시지의 동시 수신을 처리한다. |
| FR-04 | 잘못된 형식, 범위 밖 값, 과도한 길이의 메시지는 이동에 반영하지 않는다. |
| FR-05 | 중심·최솟값·최댓값 보정, 데드존, 축 반전을 적용해 두 축을 -1~1로 변환한다. |
| FR-06 | 상자는 입력 크기에 비례해 월드 X/Y 평면에서 이동한다. 대각선 최대 속도는 단일 축 최대 속도를 넘지 않는다. |
| FR-07 | 이동은 DeltaSeconds를 적용하며, 조이스틱이 데드존에 들어오면 다음 정상 입력 반영 시 정지한다. |
| FR-08 | 포트 닫기·통신 오류 시 즉시 입력을 초기화하고, 유효 입력이 0.5초 없으면 다음 Tick에서 정지한다. |
| FR-09 | 포트가 열려 있으나 입력이 없는 상태와 정상 입력 수신 상태를 구분해 표시한다. |
| FR-10 | PIE 종료 시 핸들과 입력 상태를 정리한다. 재시도 시 이전 수신 데이터가 재사용되지 않아야 한다. |

## 5. 범위와 제외 사항

이번 단계의 산출물은 Uno 스케치, UE 수신 기능, 조이스틱 보정 컴포넌트, 이동 상자 Blueprint, 테스트 맵과 사용 안내다.

다음 항목은 후속 단계로 둔다.

- SW 버튼, LED·진동·서보 등 UE→Arduino 출력과 명령 응답
- 캐릭터·카메라 제어, Enhanced Input 장치 통합
- 자동 포트 검색, 자동 재연결, 여러 장치 지원
- 물리 기반 이동, 장애물 충돌·게임 규칙
- Windows 외 플랫폼

## 6. 품질 요구사항

- 대기 데이터를 읽기 위해 게임 스레드를 기다리게 하지 않는다. Tick당 수신 작업에 상한을 둔다.
- 정상 동작 중 입력마다 로그를 출력하지 않는다. 오류는 반복 로그를 제한한다.
- 사용자가 실제 포트와 축 방향을 바꾸기 위해 C++를 수정할 필요가 없어야 한다.
- 보드 재시작이나 불완전한 메시지 때문에 상자가 임의 방향으로 이동하지 않아야 한다.

## 7. 인수 기준

| ID | 검증 | 통과 기준 |
|---|---|---|
| AC-01 | 연결 시작 | 올바른 COM 설정으로 입력 수신 상태에 도달하고 원시 축 값을 확인한다. |
| AC-02 | 중립 | 보정 후 조이스틱을 놓고 10초간 상자의 위치가 유지된다. |
| AC-03 | 방향 | 네 방향과 대각선이 설정된 축 방향과 일치하며 Z가 유지된다. |
| AC-04 | 속도 | 동일한 입력을 30/60/120 FPS에서 각각 5초 적용했을 때 이동 거리 차이가 5% 이내다. 자동 입력으로 비교하고 실제 조이스틱은 별도로 확인한다. |
| AC-05 | 대각선 | 최대 대각선 입력의 이동 속도가 설정한 최대 속도를 넘지 않는다. |
| AC-06 | 파싱 | 분할·다중 메시지는 처리하고, 잘못된 숫자·범위·길이는 거부한다. |
| AC-07 | 입력 중단 | 입력 만료 0.5초 후 다음 Tick까지 정지한다. 포트 오류를 먼저 감지하면 즉시 정지한다. |
| AC-08 | 수명주기 | PIE 시작·종료를 5회 반복한 뒤 포트를 다시 열 수 있다. |
| AC-09 | 실패·복구 | 없는 포트 또는 점유된 포트에서 명확한 실패 상태를 보이고, 원인 해소 후 수동 재시도로 복구한다. |
| AC-10 | 패키징 | Windows Development 패키지에서 동일한 연결·이동·정지 동작을 확인한다. |

## 8. 구현 착수 전 확인

- 실제 COM 번호와 사용 가능한 UE 5.8 빌드 환경
- VRx/VRy의 실제 중심과 양 끝 값, 설치 방향에 따른 축 반전
- 기존 Blueprint와 테스트 맵의 구성 및 재사용 가능 여부

이 문서는 구현 결과나 테스트 통과를 의미하지 않는다. 세부 설계와 예외 처리는 SDD를 따른다.
